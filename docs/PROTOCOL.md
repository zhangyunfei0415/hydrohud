# LG600 屏幕协议（逆向记录）

本文件记录 TCOMAS LG600 水冷头 480×480 屏幕的 USB HID 协议。所有结论都在真机上验证过；
`lg6studio/device.py` 就是这份协议的实现。逆向只针对自己拥有的硬件，目的是互操作性。

## 1. 设备识别

| 项 | 值 |
| --- | --- |
| USB ID | `VID_1A2C PID_1520` |
| 设备描述 | `TCOMAS LG600`（`DEVPKEY_Device_BusReportedDeviceDesc`） |
| 结构 | Composite Device，两个 HID 接口，UsagePage `0xFF06`（厂商自定义） |
| `MI_00` | in=441 out=441 feat=0，**控制接口** |
| `MI_01` | in=17 out=1025 feat=0，**图像接口** |

接口靠 `OutputReportByteLength` 区分（441 → 控制，1025 → 图像），不要靠 MI 编号，
因为不同主板/固件下编号可能变。

## 2. 报文格式

图像接口每个输出报文 1025 字节，头 5 字节 + 1020 字节负载：

| 偏移 | 长度 | 值 | 含义 |
| --- | --- | --- | --- |
| 0 | 1 | `0x00` | report id |
| 1 | 1 | `0x08` | 命令：图像流 |
| 2 | 1 | 首包 = 本帧分包**总数**，其余 = 1 基分包序号 | `pkt[2]` |
| 3 | 1 | `0x00` | 保留 |
| 4 | 1 | 首包 `0x80`，其余 `0x00` | 标志：本包携带 JPEG 起始 |
| 5 | 1020 | — | JPEG 字节流（不足补 `0x00`） |

- 一帧 = **15 包 × 1020 = 15300 字节**上限；官方固件只正确处理 15 包（实测 19 包花屏）。
- 没有握手、没有"进入传输模式"命令，直接连推 1025 字节报文即可。
- JPEG 为 baseline、480×480、3 分量；官方帧约 14900–15200 字节，尾部补 `0x00`。

## 3. 控制接口命令（441 字节报文）

格式与图像接口一致：`00 | cmd | 分包数/序号 | 00 | 首包 0x80 | 参数…`，参数从 wire 偏移 5 开始。

| 命令 | 参数 | 含义 | 状态 |
| --- | --- | --- | --- |
| `0x81` | — | 查询设置；回 441 字节，偏移 5 = 旋转象限 | ✅ 实测 |
| `0x12` | 0–100 | 亮度百分比（默认 100） | ✅ 实测 |
| `0x10` | 0=亮 1=灭 | 屏幕开关（唯一的息屏命令） | ✅ 实测 |
| `0x11` | 0–3 | 旋转象限（只存配置，**不旋转**推流画面） | ⚠️ 实测无可见效果 |
| `0x18`/`0x1A`/`0x1E` | 值 | 温度显示 / CPU 内容类型 / 循环播放 | 未测 |
| `0x0A` + `0x0B` | — | 写屏内 flash（12 字节块头：文件偏移/长度/进度） | 未测；可能是换开机图的入口 |

旋转要自己在软件侧转像素——官方 `XYUI` 也是这么做的，硬件 `0x11` 只改设备保存的设置。

## 4. 固件看门狗（重要）

屏幕**不锁存单帧**：只发一帧然后停下，10 秒内就会黑屏或回落官方画面。
所以静态画面必须按固定帧率重复推同一段编码好的 JPEG（30 fps 只占约 6% 带宽，很便宜）。

## 5. 抓包方法（复现用）

官方 GUI 是 32 位 MFC 程序 `C:\Program Files (x86)\TcomasSoftware\DeviceDriver.exe`，
用 Frida 挂 `kernel32!WriteFile`：

- 必须用 `Interceptor.attach`（`onEnter` 记参数、`onLeave` 读缓冲区）。
  **不要用 `Interceptor.replace`**——替换 `ReadFile` 会让这个 32 位 MFC 进程直接崩溃。
- 抓包时所有 `WriteFile` 返回 0 且 `GetLastError()==ERROR_IO_PENDING(997)`，这是
  overlapping I/O 的正常表现，**不是写失败**；同步写的本项目实现会直接返回成功。

## 6. 与官方软件的关系

同一 HID 接口同一时间只能被一个进程占用。官方 `DeviceDriver.exe` 运行时本项目打不开设备，
反之亦然；关掉对方即可。屏幕内容由最后写数据的一方决定，看门狗超时后固件自行处理。
